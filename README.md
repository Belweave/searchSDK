searchSDK is an open-source, MIT-licensed SDK by Belweave that gives AI apps
and agents one interface to many web search APIs, with explicit fallback,
per-attempt cost and open benchmarks.

There are two calls: `search` and `contents`. Each provider is described
once, as data, in [`registry/`](registry). The TypeScript and Python runtimes
read that registry; neither contains provider-specific code.

**Not live-verified yet.** Every provider spec is written from the provider's
public documentation and tested against synthetic fixtures only.

## Install

```sh
npm install @searchsdk/sdk
```

TypeScript and JavaScript, zero runtime dependencies, Node 24 or newer.

```ts
import { search } from "@searchsdk/sdk";

// Reads EXA_API_KEY from the environment.
const { results, cost } = await search("sqlite wal mode", { provider: "exa" });
console.log(results[0]?.title, results[0]?.url, cost.usd);
```

For fallback, retries and page text, create a client:

```ts
import { createClient } from "@searchsdk/sdk";

const client = createClient({ provider: "tavily", fallback: ["exa"], maxRetries: 1 });
const res = await client.search("eu ai act", { recency: "month", timeoutMs: 10_000 });
const pages = await client.contents(res.results.map((r) => r.url), { provider: "exa" });
console.log(res.attempts, pages.cost);
```

Every response carries its `cost` in USD (reported, estimated from list
prices, or `null` when unknown) and every `attempt`, each marked billed `yes`,
`possible` or `no`, so retries and fallback never hide spend. Failures throw
`SearchError` with a fixed `code`. Retries and fallback are off unless you
set them. Keep provider keys on the server. Full API: the
[TypeScript README](sdk/typescript/README.md) and
[searchsdk.dev/docs](https://searchsdk.dev/docs).

### Python

Python 3.10 or newer, standard library only. Not on PyPI yet; install from
source:

```sh
git clone https://github.com/Belweave/searchSDK
python -m pip install ./searchSDK/sdk/python
```

```python
import searchsdk

response = searchsdk.search("sqlite wal mode", provider="exa")
print(response.results[0].title, response.cost.usd)
```

See the [Python README](sdk/python/README.md).

`EXA_API_KEY`) or are passed to the client. "Unverified" means no
endpoint has passed its conformance vectors against the live API yet.
Provider names and logos are trademarks of their owners; searchSDK is not
affiliated with or endorsed by any provider.

## Benchmarks

searchSDK Benchmarks measures providers through the TypeScript runtime,
exactly as users call them. The method is version 0.4.0
([bench/METHOD.md](bench/METHOD.md)). The first full run is in progress;
**no results are published yet**, and the site shows "Results pending" until
they are. CI runs the harness on synthetic fixtures only.

## Repository

| Path | What |
| --- | --- |
| [`registry/`](registry) | Provider specs, named steps, shared policy and conformance vectors |
| [`sdk/typescript/`](sdk/typescript) | `@searchsdk/sdk`, the TypeScript runtime |
| [`sdk/python/`](sdk/python) | `searchsdk`, the Python runtime |
| [`bench/`](bench) | The benchmark harness, datasets and method |
| [`site/`](site) | [searchsdk.dev](https://searchsdk.dev): Next.js and Fumadocs |
| [`brand/`](brand) | Brand sources, exports, tokens and fonts |
| [`docs/`](docs) | An index of the docs, and the [release guide](docs/releasing.md) |
| [`scripts/`](scripts) | Repository checks |

Each package installs and checks on its own. From the root, `npm run setup`
installs them all and `npm run check` runs every check CI runs. No check
needs a provider key or calls a provider.
