Uploads and ingestion operations API


To upload files, use a workspace API key with 
Read / Write
 permission. You can also use an access token from a user who is a workspace editor or admin. A 
Search Only
 key is enough to check an operation’s status. Save the upload, drive, and workspace IDs so you can check progress later.


See 
authentication
 for request headers and response formats, and 
error recovery
 for help with failed requests.


Upload sequence




Prepare an upload with filename, format, byte length, SHA-256 digest, and external ID.


Obtain transfer instructions and send the original bytes using the selected transport.


Complete the upload to queue processing.


Read upload and operation status until the content is searchable.




Use the 
Python upload workflow
 when you want the client to handle hashing, transfers, and polling.


Bulk file uploads


For several files, bulk requests let you reserve uploads, complete transfers, and check progress with fewer API calls. The 
Python SDK
 handles these steps automatically. Each file has its own outcome, so your application can keep successful uploads and follow up on individual files that need attention.


Use 
Content-Type: application/json
 for each POST below. Each request accepts 1–50 unique entries and a JSON body up to 65,536 bytes. All entries belong to the drive in the URL. Reservation and completion require content-write access; status and capabilities use the drive’s read access. These routes support workspace API keys and authorized user sessions.

Bulk imports


Bulk imports load a large collection of text files into one drive. They are available only to organizations that have them enabled. For other organizations, the import routes return 404 
not_found
.


An import groups files into chunks. You declare the totals, upload each chunk to its own upload URL, acknowledge it, then seal the import. Documents become searchable over time after their chunk is acknowledged, while later chunks are still uploading. Use the same access as 
file uploads
. Choose a new UUID for each import and keep it: the import ID makes creation safe to retry, so these routes do not use 
Idempotency-Key
.


While an import batch is being applied to a drive, other writes to that drive (uploads, document changes and deletes) return 503 
temporarily_unavailable
. Retry them later. Other drives are not affected.

PUT 
/v1/drives/{drive_id}/imports/{import_id}

{"source_bytes": <total>, "documents": <total>}

POST 
/v1/drives/{drive_id}/imports/{import_id}/chunks


Declare 1 to 32 chunks: 
{"chunks":[{"sequence":0,"sha256":"<hex>","encoded_bytes":4096,"source_bytes":4000,"documents":12}]}

idempotency_conflict

POST 
/v1/drives/{drive_id}/imports/{import_id}/chunks/{sequence}/acknowledge


Send 
{}

 means the chunk has not been stored yet. 409 
idempotency_conflict

POST 
/v1/drives/{drive_id}/imports/{import_id}/seal


Send the final totals: 
{"chunks": <count>, "source_bytes": <total>, "documents": <total>}

idempotency_conflict

Bulk imports can be paused for maintenance. While paused, creating an import returns 503

Progressive import progress


For

, the operation response also includes 
progress

Field
Meaning

Number of documents accepted in this request.

Documents whose associated work has become searchable.

Documents associated with failed processing work.


Indexed documents become searchable as their part of the request is published, so

Upload timings and drive queues


Use these fields to see how long uploads take and how much work is waiting. Check the upload state and associated operation to find out when a document is searchable.


A successful 
/complete
 saves the file for processing and makes its transfer slot available for another file. Processing continues after your client disconnects. See 
upload capacity
.


Upload completion timings


GET /v1/drives/{drive_id}/uploads/{upload_id}

Field
Meaning
