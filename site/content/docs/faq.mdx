## What is searchSDK?

An open-source SDK by Belweave that gives AI apps and agents one interface to many web search APIs. Your server calls `search` or `contents`; searchSDK calls the provider you name.

## Which providers does it support?

<ProviderNames />. [Their pages](/providers) list options, prices and limits.

## How does fallback work?

Off unless you set it. A call whose provider times out, is down, rate limited, out of quota or cannot honour an option then tries the next provider in your list. Every attempt is recorded.

## How is cost reported?

Every response and attempt carries a cost and its source: reported by the provider, computed from the list price, or unknown. An unknown price is `null`, never 0.

## How does the benchmark work?

Every provider gets the same queries. Known-answer tasks rank dependable providers; latency and cost never change rank. The 404-query run is on [Benchmarks](/benchmarks); judged scores wait for 100 human labels. [Method](/docs/benchmarks-method).

## How is it different from calling a provider directly?

One result shape, one id to change, explicit fallback and per-attempt cost. A direct call gets every provider feature first. [The comparison](/docs/vs-provider-apis).

## Is it on npm or PyPI?

TypeScript is on npm as [`@searchsdk/sdk`](https://www.npmjs.com/package/@searchsdk/sdk). Python installs from source ([README](https://github.com/Belweave/searchSDK/tree/main/sdk/python)). Firecrawl is conformance-verified live; four providers are live-tested.

## What license is it under?

MIT. [Source on GitHub](https://github.com/Belweave/searchSDK).
