`warnings` holds notes that do not fail the call. Each has a `code`, the `provider`, and a `message` or `count` when there is one.

## From searchSDK

| Code | Meaning |
| --- | --- |
| `fallback_key_missing` | A fallback provider has no key and will be skipped. |
| `fallback_used` | The answer came from a fallback, not the first provider. |
| `invalid_rows_dropped` | Results or pages without a URL were dropped; `count` says how many. |
| `unmatched_pages` | The provider returned pages that match no requested URL (by URL key); `count` says how many. |

## From provider responses

The registry maps these from a provider's own body.

| Code | Meaning | Sent by |
| --- | --- | --- |
| `partial_results` | The provider says its answer is partial. | Context.dev search, Context.dev contents |
| `provider_notice` | The provider's own notice, with its `message`. | Exa search |
| `provider_warning` | The provider's own warning, with its `message`. | Exa search, Firecrawl search, Firecrawl contents |

Check warnings after every call: `fallback_used` means another provider answered, and its prices and fields differ.
