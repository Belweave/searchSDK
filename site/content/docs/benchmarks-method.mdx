---
title: Benchmarks method
description: How searchSDK benchmarks web search providers end to end, scores answer quality and ranks the leaderboard.
---

Every provider runs the same queries through searchSDK, end to end, with settings tuned to suit it. The harness is open, so anyone can rerun it with their own keys.

## The run

- About 400 queries, once a month.
- Each query goes to every provider with the same deadline and result limit.
- Every response, failure and timing is recorded.

## Quality

- **Known-answer tasks** set the rank. Each query has a checked answer. A provider scores when its top results, or the pages behind them, contain it. The harness reads those pages itself, obeying robots.txt, so no provider fetches for its rivals. A page it cannot read counts the same for everyone.
- **Judged relevance** is a separate column. One model grades results against a published rubric. People check a sample, and the column appears only when they agree with it.

## Ranking

1. Providers with fewer than 95% usable responses are marked unreliable and ranked below every dependable one.
2. The known-answer score decides the rest.
3. Two providers are tied unless the gap is statistically clear and at least 6 points.

Latency and cost are reported beside the rank. Cost never changes rank.

## Funding

Runs are paid for by provider credits, donations and a capped monthly budget from the maintainer. Every source is disclosed with the results.
